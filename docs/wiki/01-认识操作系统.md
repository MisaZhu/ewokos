# 01 认识操作系统

> 本章不需要写代码。目标是建立心智模型：操作系统是什么、为什么需要它、
> 微内核与宏内核之争、EwokOS 的源码仓库如何组织。读完本章你应该能回答：
> "我接下来要写的每一个东西，最终会落在系统的哪个位置？"

## 1.1 什么是操作系统

你打开手机点个外卖：屏幕亮起、程序读取位置、数据通过无线网络收发、
结果存进本地文件，同时后台还有音乐在播、消息在收。
这些活，应用程序自己一件也做不了——微信不控制屏幕，美团不驱动网卡。
它们只会一件事：**请求**。真正干活的是操作系统。

一句话定义：

> **操作系统是运行在硬件之上的第一个程序，也是永远不退出的程序。
> 它管理硬件，并为所有其他程序提供服务。**

三个关键词：**第一个**（其他程序都由它启动）、**永不退出**（从开机到关机一直在）、
**管理 + 服务**（对下管硬件，对上供服务）。

把它想象成餐厅总管家：安排厨师用锅（**进程调度**）、给每桌分独立餐区
（**内存管理**）、前厅后厨传话（**进程间通信**）、客人按铃有人应（**中断处理**）、
客人不许自己进厨房拿刀（**系统调用**守门）。每项工作在本教程都有对应的实验章节，
见本章末尾的路线图。

## 1.2 为什么需要操作系统

用三个场景说明没有它会乱成什么样：

**场景一：两个程序抢 CPU。** 没有规矩时，要么排队跑（一个死循环全完），
要么靠程序自觉让出（忘写的霸占，恶意的不让）。操作系统的解法：
时钟硬件定期打断 CPU（时钟中断），由操作系统的代码决定下一个谁跑——
公平靠硬件保证，不靠自觉。→ 第 06、07 章。

**场景二：两个程序踩内存。** 程序 A 的数据在地址 `0x1000`，程序 B 也写 `0x1000`，
A 的数据就被改坏了。操作系统的解法：给每个程序一张独立的地址翻译表（页表），
A 的 `0x1000` 翻译到物理第 5 页，B 的 `0x1000` 翻译到第 9 页——
同一个"门牌号"，不同的"房子"，越界访问直接被硬件拒绝。→ 第 05 章。

**场景三：程序直接碰硬件。** 任何程序都能读写的硬件寄存器，意味着任何程序
都能把系统搞坏。操作系统的解法：CPU 分两个"档位"（特权级），
危险操作只允许内核态做；用户态程序想办事，只能通过系统调用请求内核代劳。
→ 第 04、08 章。

合起来就是操作系统的三大价值：**用硬件强制的公平替代自觉，
用地址翻译的隔离替代共享，用特权级的门禁替代不设防**。

## 1.3 计算机开机后到底发生了什么

一台裸机（以树莓派为例）通电时，内存是空的，CPU 只会做一件事：**从固定位置开始执行指令**。
此时没有软件、没有文件、没有任何"系统"可言。

要让这台机器"有用"，需要一层层把软件垫起来：

```
┌─────────────────────────────────────────┐
│  你的应用程序（浏览器、游戏、终端……）        │  ← 用户态
├─────────────────────────────────────────┤
│  系统服务（文件系统、窗口系统、网络栈……）    │  ← 用户态（EwokOS 的选择）
├─────────────────────────────────────────┤
│  操作系统内核（进程管理、内存管理、中断……）  │  ← 内核态
├─────────────────────────────────────────┤
│  硬件（CPU、内存、SD 卡、显卡、串口……）     │
└─────────────────────────────────────────┘
```

**操作系统内核**就是垫在硬件上的第一层软件。它的工作只有几件，但每一件都是地基：

| 职责 | 说明 | 对应本教程章节 |
|------|------|--------------|
| 启动引导 | 把 CPU/内存/设备初始化到可用状态 | 03、04、05 |
| 内存管理 | 让每个程序以为自己独占内存，互不踩坏 | 05 |
| 中断与异常 | 及时响应硬件事件（按键、定时器、缺页） | 04、06 |
| 进程管理 | 让多个程序"同时"运行 | 07 |
| 系统调用 | 给上层提供受控的入口 | 08 |
| 设备驱动 | 驱动 SD 卡、串口、显卡等硬件 | 10、13 |

## 1.4 裸机程序与操作系统的区别

你可以写一个直接操作硬件的程序（比如点亮一个 LED），这叫**裸机程序（bare-metal program）**。
它的特点是：

- 只有**一条执行流**，没有"多任务"概念；
- 所有代码都能访问所有内存和所有设备，没有保护；
- 没有文件系统，数据只能写死在代码里或手动读写扇区。

操作系统 = 裸机程序 + **多任务** + **内存保护** + **抽象层**（文件、进程、管道等）。
本教程第 03 章你会先写一个裸机程序，之后每一章给它加一层能力，最终它就长成了操作系统。

## 1.5 微内核和宏内核：伤友情的话题

内核设计有一个根本分歧：**多少功能放进内核态？** 答案不同，形成两大阵营。

**宏内核（Monolithic）**：文件系统、驱动、网络栈全部编译进内核，
和内核一起运行在最高特权级。Linux 就是这种。
优点是性能好（都在内核里直接函数调用），缺点是驱动一个 bug 就能搞死整个系统。

**微内核（Microkernel）**：内核只保留最小职责——进程调度、内存管理、
中断处理、系统调用、进程间通信（IPC）。文件系统、驱动、网络栈统统作为
**普通用户程序**运行。某个驱动崩了，系统不会死，重启它即可。

这不是新话题。1992 年，Linux 之父 **Linus Torvalds** 与 Minix 作者、
操作系统教科书泰斗 **Andrew Tanenbaum** 在网上展开过一场载入史册的论战
（史称 Tanenbaum–Torvalds debate）：

- Tanenbaum：微内核是未来。宏内核把海量代码塞进内核态，一个驱动出错
  整个系统崩溃，架构上是过时的设计。
- Torvalds：**性能和实用**更重要。微内核里驱动跑在用户态，访问硬件
  都要跨进程通信，开销太大。Linux 能跑、好用、免费，这才是硬道理。

两边都没说错，分歧在价值排序：

| | 宏内核 | 微内核 |
|---|---|---|
| 内核内调用 | 直接函数调用，快 | 需要消息传递，慢一些 |
| 可靠性 | 一个模块崩，全系统崩 | 一个服务崩，只影响它自己 |
| 安全性 | 内核态代码庞大，攻击面大 | 内核态代码极小，易于审计 |
| 驱动开发 | 在内核里写，踩雷即死机 | 驱动是普通程序，崩了重来 |
| 可移植性 | 驱动与内核纠缠，移植难 | 内核小，移植容易 |

所以这个话题"伤友情"——不是对错之争，而是取舍之争。
今天的手机（Linux/Android）和安全芯片（往往是微内核）同时在用两种设计。
而当年的"微内核太慢"，后来被 L4 微内核家族的极致优化和
QNX、Fuchsia 的大规模商用证明已不再是硬伤。

### 本教程为什么写微内核

对做产品的人，宏内核生态无敌；对**学操作系统**的人，微内核有压倒性优势：

1. **内核小到能全部看懂**。EwokOS 内核核心只有几千行，覆盖的恰恰是
   操作系统的五个本质机制。宏内核几千万行，没人能通读。
2. **驱动崩了不死机**。用户态写驱动，一个指针错误只是该进程崩溃，
   学习阶段这是"成就感"与"挫败感"的分水岭。
3. **被迫学会 IPC**。微内核里驱动、文件系统、窗口系统全靠消息协作，
   你会看到"操作系统 = 一群进程通过消息协作"的完整图景。
4. **代码终点就是微内核**。本教程从裸机一路写到迷你多任务系统，
   最后与 EwokOS 的结构严丝合缝。

EwokOS 是**微内核**。这是理解本仓库一切设计的关键：

```
用户态:  /sbin/init  /sbin/core  /sbin/vfsd  /sbin/sdfsd  /bin/shell
         /drivers/uartd  /drivers/timerd  /drivers/xserverd ...
              │            │          │            │
              └────────────┴──── IPC ─┴────────────┘   ← 一切靠消息传递
              ┌────────────────────────────────────┐
内核态:       │  调度器  内存管理  中断  系统调用  IPC │  ← 内核只有这些
              └────────────────────────────────────┘
```

比如"读取文件"在 EwokOS 里的流程是：

1. 你的应用调用 `open("/a.txt")`；
2. 库函数把它变成一个 **IPC 请求**发给文件系统守护进程 `vfsd`；
3. `vfsd` 再把请求转发给 SD 卡文件系统进程 `sdfsd`；
4. `sdfsd` 读 SD 卡硬件，把数据原路返回。

内核全程只负责传递消息和切换进程，**不理解什么是"文件"**。
这个机制（IPC）是第 09 章的主角，它是微内核的血液。

## 1.6 EwokOS 源码地图

打开仓库根目录，最重要的几个目录：

```
ewokos/
├── kernel/                 内核源码（平台无关部分）
│   ├── kernel/             核心：进程、调度、内存、IPC、系统调用
│   │   ├── include/        内核头文件（进程结构体、系统调用号等）
│   │   └── src/            实现：proc.c、schedule.c、ipc.c、svc.c、mm/...
│   ├── platform/           平台相关代码（arm / aarch64 / riscv / x86）
│   │   └── aarch64/arch/v8/boot.S   ← CPU 上电后执行的第一条代码
│   ├── lib/                内核工具库（字符串、printf、ext2 读取、sconf 配置）
│   ├── dev/                设备接口（串口、定时器、SD 卡的统一抽象）
│   └── loadinit/           从 SD 卡加载 init 进程的代码
│
├── machines/               各个真实硬件板子的"板级支持包"(BSP)
│   ├── raspix/             ★ 树莓派 2B/3B/4B（本教程的目标板）
│   │   ├── kernel/         树莓派的内核配置与驱动（UART、SD 卡、中断）
│   │   └── system/         树莓派的系统构建入口与启动脚本
│   ├── miyoo/  orangepi/  raspi5/ ...     其他板子
│   └── x86/  virt.riscv/
│
├── machine.virt/           QEMU 虚拟机目标（开发和实验最方便）
│   ├── kernel/             虚拟机的内核构建
│   └── system/             虚拟机的系统构建
│
├── system/                 用户态代码（与板子无关的部分）
│   ├── basic/              基础层：libc、init、shell、核心命令、基础驱动
│   │   ├── libc/           C 库（libewoksys + libgloss）
│   │   ├── sys/            核心系统进程：init、core、vfsd、sdfsd、sessiond
│   │   └── bin/            命令行工具：ls、cat、shell、ps ...
│   ├── network/            TCP/IP 协议栈与网络服务
│   ├── gui/                图形库与 framebuffer 驱动
│   ├── xwin/               X 风格窗口系统（xserverd、窗口管理器）
│   └── platform/           各架构的编译规则（make.rule）
│
├── sw.extra/               可选的第三方软件（SDL2 等）
├── tools/                  SD 卡制作脚本与启动固件文件
└── docs/                   文档（你正在读的教学就在这里）
```

记住一条主线：**`kernel/` 是通用内核，`machines/raspix/` 是树莓派定制层，
`system/` 是所有板子共享的用户态**。构建系统把它们拼在一起。

## 1.7 EwokOS 启动全景图

先把启动全过程粗略过一遍，之后每一章都会展开其中一步：

```
① 树莓派上电，GPU 固件读取 SD 卡上的 config.txt，
   把 kernel8.img（我们的内核）加载到内存 0x80000 处并跳转执行
        ↓
② boot.S：CPU 从特权级 EL2 切到 EL1，关中断、设栈，进入 C 代码
        ↓
③ start.c/_boot_start：建立启动页表，打开 MMU（虚拟内存）
        ↓
④ kernel.c/_kernel_entry_c：初始化内存分配器、串口、
   读内核配置文件，建立进程表，加载第一个用户进程 /sbin/init
        ↓
⑤ init 进程：启动核心服务（core、vfsd、sdfsd），
   然后执行 /etc/init.rd 启动脚本，拉起串口驱动、终端会话……
        ↓
⑥ 你看到命令行提示符，可以输入命令了
```

## 1.8 跟着做：感受一次完整启动

## 1.9 本章小结

- 操作系统是垫在硬件上的第一层软件，用调度、隔离、门禁三招管理机器；
- 裸机程序只有一条执行流、没有保护和多任务，是 OS 的雏形；
- 宏内核与微内核之争是取舍之争；本教程选微内核：内核小得能看懂、
  驱动崩了不死机、被迫学会 IPC；
- EwokOS 是微内核：内核只做调度/内存/中断/系统调用/IPC，
  驱动和文件系统都是用户态进程；
- 源码三大块：`kernel/`（内核）、`machines/raspix/`（树莓派板级）、`system/`（用户态）。
