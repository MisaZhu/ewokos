# 02 开发环境搭建

> 本章目标：装好所有软件工具、备齐硬件，第一次编译并运行 EwokOS。
> 支持 macOS 和 Linux（Ubuntu/Debian）。整个过程只用命令行。
> 软件部分是必做的；硬件部分可以先跳过（QEMU 能完成前 13 章的全部实验），
> 到第 14 章真机烧录前再备齐也来得及。

## 2.1 我们需要哪些软件工具

在你的电脑上开发树莓派的操作系统，涉及三个概念：

1. **交叉编译器（Cross Compiler）**：你的电脑是 x86/ARM Mac，而目标程序要跑在
   ARM 树莓派上，所以需要一个"能生成 ARM 代码的编译器"。
   - `arm-none-eabi-gcc`：生成 32 位 ARM 代码
   - `aarch64-none-elf-gcc`：生成 64 位 ARM（AArch64）代码 ← 本教程主线
   - `none` 表示"裸机"：这些编译器生成的程序不依赖任何操作系统（正是我们要的）。
2. **QEMU**：硬件模拟器，可以在你的电脑上模拟出一块树莓派（`raspi3b`/`raspi2b`），
   免去反复烧录 SD 卡。
3. **文件系统工具**：`mke2fs`（格式化 ext2/ext3）、`e2cp`（往镜像里拷文件）。

## 2.2 macOS 安装

```bash
# 安装 QEMU、文件系统工具
> brew install qemu e2tools e2fsprogs

# 安装 ARM 官方交叉工具链（包含 arm-none-eabi 和 aarch64-none-elf）
> brew install --cask gcc-arm-embedded
```

如果 brew 的 cask 版本不满足需要，也可以到
[Arm Developer 官网](https://developer.arm.com/downloads/-/arm-gnu-toolchain-downloads)
下载 `arm-gnu-toolchain-*-mac-*-aarch64-none-elf.pkg` 与
`arm-gnu-toolchain-*-mac-*-arm-none-eabi.pkg` 安装。

## 2.3 Linux (Ubuntu/Debian) 安装

```bash
> sudo apt install qemu-system-arm qemu-system-misc e2tools e2fsprogs

# 32 位 ARM 工具链
> sudo apt install gcc-arm-none-eabi

# 64 位 AArch64 裸机工具链（aarch64-none-elf-gcc）
# Ubuntu 仓库没有裸机版，请从 Arm 官网下载：
#   https://developer.arm.com/downloads/-/arm-gnu-toolchain-downloads
# 下载 arm-gnu-toolchain-*-x86_64-aarch64-none-elf.tar.xz 后：
> sudo tar xf aarch64-none-elf.tar.xz -C /opt/
> export PATH=$PATH:/opt/arm-gnu-toolchain-*-aarch64-none-elf/bin
# 建议把上一行写进 ~/.bashrc
```

## 2.4 验证工具链

```bash
> aarch64-none-elf-gcc --version
> arm-none-eabi-gcc --version
> qemu-system-aarch64 --version
```

三个命令都能输出版本号即成功。

## 2.5 获取源码与编译约定

获取 EwokOS 源码（如果你还没有的话），并放在推荐路径：

```bash
> mkdir -p ~/work && cd ~/work
> git clone <EwokOS 仓库地址> ewokos
> cd ~/work/ewokos
```

EwokOS 的 Makefile 用环境变量 `ewokos` 定位源码根目录，**默认值就是 `~/work/ewokos`**。
所以把仓库放在 `~/work/ewokos` 最省事；放在别处则每次构建前需要：

```bash
> export ewokos=/你的/路径/ewokos
```

### 构建目标的选择

仓库里有多个可构建目标：

| 目录 | 说明 |
|------|------|
| `machine.virt/` | QEMU `virt` 虚拟机，外设是 VirtIO，启动快，**日常开发首选** |
| `machines/raspix/` | 树莓派 2B/3B/4B，可 QEMU 模拟也可上真机 |

建议先用 `machine.virt` 跑通全流程，再编译 `raspix`。

## 2.6 跟着做：第一次编译并运行

```bash
> cd machine.virt/system
> make            # 全量构建：内核 + 用户态 + SD 镜像，首次约 10~30 分钟
> make run        # 启动 QEMU
```

编译树莓派目标：

```bash
> cd machines/raspix/system
> make          # 默认 HW=raspix ARCH=aarch64（见 make.inc）
> make run      # QEMU 模拟树莓派 3B
```

> 提示：退出 QEMU 按 `Ctrl-A` 然后按 `x`。

## 2.7 理解构建系统在做什么

EwokOS 用**分层递归 Make** 构建，你暂时只需要知道流程：

```
machines/raspix/system/Makefile            ← 入口（选择板子）
  ├── ../kernel/Makefile                   ← 编译内核 → kernel8.img
  ├── system/platform/aarch64/make.rule    ← 定义编译器与编译参数
  ├── system/basic/                        ← C 库、init、shell、命令
  ├── system/network/                      ← 网络协议栈
  ├── system/gui/                          ← 图形库与显示驱动
  ├── system/xwin/                         ← 窗口系统
  └── sd 目标                              ← 把所有产物打包成 ext3 镜像
```

每一层只依赖下一层的产物。`make.rule` 里定义了类似这样的内容
（见 [system/platform/aarch64/make.rule](../../system/platform/aarch64/make.rule)）：

```make
CC = aarch64-none-elf-gcc
CFLAGS = -march=armv8-a -ffreestanding ...
```

`-ffreestanding` 表示"独立环境"：编译器不能假定存在任何标准库——
因为我们就是在**制造**那个环境。

## 2.8 调试准备：GDB

内核级 bug 常常表现为"直接卡死/重启"，这时候断点调试是救命稻草。
在两个终端里分别执行：

```bash
# 终端 1：以调试模式启动（暂停在第一条指令等待 GDB 连接）
> cd machines/raspix/kernel
> make debug

# 终端 2：启动 GDB 并自动连接
> make gdb
```

常用 GDB 命令：`b 函数名`（打断点）、`c`（继续）、`s`（单步）、`p 变量`（查看）。

## 2.9 硬件环境准备（可选，但强烈建议）

QEMU 能模拟出几乎全部功能，但**在真实的树莓派上看到自己写的系统跑起来**，
是完全不同的体验——这也是本教程的最终目标。需要三样东西：

### ① 一块树莓派

| 型号 | 支持情况 | 说明 |
|---|---|---|
| Raspberry Pi 3B / 3B+ | ★ 推荐 | EwokOS 主线支持，资料最多 |
| Raspberry Pi 4B | 支持 | 性能更强，外设基址略有差异（代码已适配） |
| Raspberry Pi 2B | 支持 | 32 位路线（ARCH=arm） |
| Raspberry Pi Zero 2W | 支持 | 便宜小巧，核心与 3B 相同 |

### ② 一张 MicroSD 卡（8GB 以上）

系统镜像约 512MB，8GB 绰绰有余。烧录方法在第 14 章详述。

### ③ 一根 USB 转 TTL 串口线（重点！）

树莓派跑我们自己的系统时，**屏幕、键盘都不一定可用**，
所有启动日志和命令行都通过串口输出。所以串口线是调试真机的生命线。

选购要点：**必须是 3.3V 电平的 TTL 线**（常见的是 PL2303/CP2102/FT232 芯片），
不能用 5V 的 RS232 线，否则可能烧坏树莓派。线序通常是黑（GND）、白/绿（RX）、绿/白（TX）。

接线（以 40 针 GPIO 为准）：

```
USB-TTL 线        树莓派 GPIO
──────────        ──────────
GND   (黑)   ───→  Pin 6  (GND)
RX    (收)   ───→  Pin 8  (GPIO14, 树莓派的 TX)
TX    (发)   ───→  Pin 10 (GPIO15, 树莓派的 RX)
VCC   (红)   ───→  不接！（树莓派用自己的电源）
```

> 注意两点：**RX 接对方的 TX**（交叉）；**VCC 红线悬空不接**，
> 树莓派用 USB 电源单独供电。

电脑端打开串口终端（波特率 **115200**，8N1）：

```bash
# macOS（先 ls /dev/cu.* 找到设备名）
> screen /dev/cu.usbserial-xxxx 115200     # 退出：Ctrl-A 然后按 K

# Linux
> sudo minicom -D /dev/ttyUSB0 -b 115200    # 或 picocom
```

至此软件与硬件都已就绪。第 14 章会把镜像烧进 SD 卡、插上串口线，
在真机上看到自己写的操作系统启动。

## 2.10 本章小结

- 交叉编译器让我们在自己的电脑上编译出树莓派可执行的代码；
- QEMU 让我们不必烧卡就能运行整个系统；
- 真机三件套：树莓派（推荐 3B）、SD 卡、3.3V USB-TTL 串口线；
- 构建入口是 `machine.virt/system`（开发）或 `machines/raspix/system`（树莓派）；
- 你已经成功启动了一次完整的 EwokOS。

下一章，我们抛弃所有现成的东西，从第一行汇编开始写一个属于自己的裸机程序。
