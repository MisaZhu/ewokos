# 06 中断与定时器

> 本章目标：理解中断机制与中断控制器，看懂 EwokOS 如何响应硬件事件，
> 重点理解定时器中断如何驱动整个系统的"心跳"和进程调度。
> 本章对应实验主线的"第 2 套代码"：鼓起勇气往深水去前进一点。
> 本章术语（IRQ/FIQ/GIC/EOI/Timer…）见 [附录·术语表](99-术语表-专业名词速查.md)。

## 6.1 为什么需要中断

假设没有中断，内核想知道"键盘有没有按键"只能不停地查询设备状态寄存器
（轮询，polling）。轮询浪费 CPU，而且越晚查到就越迟响应。

**中断**让硬件主动通知 CPU：

```
CPU 正在执行进程 A
        │
SD 卡读完数据 ──► 中断控制器 ──► 给 CPU 发 IRQ（Interrupt Request，中断请求）信号
        │
CPU 硬件自动：停下 A，保存现场，跳进内核中断处理代码
        │
内核：取走数据，唤醒等待的进程
        │
恢复现场（可能换成进程 B 继续）
```

中断就是第 04 章"异常"的一种。处理框架完全复用：向量表入口 →
保存上下文 → C 处理 → 恢复 → `eret`。

## 6.2 熟悉树莓派的中断：中断从哪来

树莓派 3B 的中断源大约有 60 多个，全部汇总到博通中断控制器的
三个状态寄存器里（`IRQ_BASIC_PENDING`、`IRQ_PENDING_1`、`IRQ_PENDING_2`）。
对本教程重要的有这几个：

| 中断源 | 编号 | 谁来处理 | 意义 |
|---|---|---|---|
| 定时器（ARM generic timer） | BASIC 5 | 内核 | 心跳与调度（本章主角） |
| Mini UART | IRQ1 29 | 用户态 `uartd` | 串口收发 |
| AUX（SPI1/2 共享） | IRQ1 29 | 用户态驱动 | 外设 |
| EMMC（SD 卡） | IRQ2 30 | 用户态 `sdd` | 存储 |
| GPIO | IRQ1 49/50 | 用户态驱动 | 按键等 |

**熟悉中断 = 熟悉这张表**。每接手一个新设备，第一件事就是查它的中断号，
然后照着同一套路：使能 → 等中断 → 处理 → 清标志。

## 6.3 中断处理的基本方法

不管什么中断，处理方法都是固定的四步，把它当成一个模板：

```
① 使能：  写中断控制器的使能寄存器 + 打开 CPU 的总开关（DAIF）
② 识别：  中断来了，读 pending 寄存器，看是哪一路设备
③ 处理：  干活（取数据/记账/唤醒进程），越快越好
④ 清标志：写设备的"清中断"寄存器 + 通知控制器"处理完了"，
          否则同一个中断会疯狂重入
```

对照 EwokOS 树莓派 BSP 的真实代码
（[irq_pix.c](../../machines/raspix/kernel/bsp/pix/irq_pix.c)，节选）：

```c
// ② 识别：逐个检查状态寄存器
uint32_t pend = get32(IRQ_PENDING_1);
if(pend & (1 << 29)) { /* Mini UART 有中断 */ }

// ④ 清标志：写设备的清中断位（以 AUX 为例）
put32(AUX_MU_IIR, 0x4);   // 写 1 清中断标志
```

四步里最容易出的 bug 是**忘了第 ④ 步**：中断标志没清，
CPU 刚返回又被同一个中断拉回来，系统表现为"卡死"。
真机调试时如果系统启动后莫名冻结，先怀疑这里。

## 6.4 中断控制器：GIC

现代 ARM 芯片不把所有设备的电线直接接在 CPU 上，而是接在一个叫
**GIC（Generic Interrupt Controller）**的芯片模块里。它负责：

1. 汇集所有设备的中断请求；
2. 按优先级裁决（多个中断同时到来时先给谁）；
3. 把选中的中断发给对应的 CPU 核心；
4. 提供寄存器让内核**使能/屏蔽**某个中断、查询是哪个中断、通知"处理完了"。

不同芯片的 GIC 版本和寄存器不同，所以 EwokOS 把这部分放在平台层：
[gic.c](../../kernel/platform/aarch64/arch/common/src/gic.c)。

树莓派 3B 用的却是博通自家的中断控制器（不是标准 GIC），
在 [irq_pix.c](../../machines/raspix/kernel/bsp/pix/irq_pix.c)：

```c
void irq_enable_pix(uint32_t irq) {
    if(IRQ_TIMER0 == irq){
        *((uint32_t*)ENABLE_BASIC_IRQS) = (1 << 5);  // 写寄存器使能定时器中断
    }
}
```

这正是第 03 章说过的套路：**查手册、找寄存器、写内存**。
板子不同（Pi3/Pi4）只是寄存器地址不同，所以树莓派 BSP 里分了
`pix/`（Pi2/Pi3）和 `pi4/`（Pi4）两套。

## 6.5 操作系统的心跳：时钟，赋予它生命

到目前为止，我们的内核还是一个"被动"的程序：没人叫它，它就不动。
定时器中断改变这一切——**从打开时钟的那一刻起，系统有了自己的心跳，
也就有了"生命"**：它每隔 ~1 毫秒醒来一次，主动检查有没有进程该换、
有没有时间账要记、有没有等待的进程到期该唤醒。

所有中断里最重要的是**定时器中断**——它按固定频率触发，是操作系统的时间来源。

### 设置频率

内核启动的最后一步（[kernel.c](../../kernel/kernel/src/kernel.c)）：

```c
timer_set_interval(0, _kernel_config.timer_freq);  // 默认 1024 次/秒
__irq_enable();                                    // 打开总中断开关
```

`timer_freq` 来自配置文件 `/etc/kernel/kernel.conf`（第 11 章讲配置），
默认 1024，即**每 ~0.98 毫秒**一次定时器中断——这就是内核的心跳。

树莓派的实现（[timer.c](../../machines/raspix/kernel/bsp/timer.c)）
直接写 ARM 的通用定时器寄存器：

```c
inline void write_cntv_tval(uint32_t tval) {
    __asm volatile("msr CNTV_TVAL_EL0, %0" : : "r" (tval) : "memory");
}
// 写入倒计时值，倒数到 0 就触发一次中断
```

### 中断到来时发生什么

中断总入口在 [irq.c](../../kernel/kernel/src/irq.c)，核心逻辑：

```c
// 定时器中断处理（简化）：
timer_clear_interrupt(0);   // ① 清中断标志，并重装下一次倒计时
...
schedule(ctx);              // ② 趁机做调度！换下一个进程运行
```

关键设计：**每次定时器中断都是一次"强制换人"的机会**。
进程 A 正在跑，时间片到了，中断把它打断，内核在返回前调用
`schedule()` 换成进程 B。这样任何进程都无法霸占 CPU——
**抢占式多任务**就是这样实现的（调度器细节见第 07 章）。

此外内核还在中断里记账（累计系统运行时间、各进程用掉的 CPU 时间），
这些数据就是 `ps` 命令显示的统计信息。

## 6.6 内核中断处理的分层

EwokOS 的中断代码分三层，职责清晰：

```
① 平台汇编层  interrupt.S          保存/恢复全部寄存器（第 04 章）
        │
② 板级层     machines/raspix/bsp/  判断是哪个中断（读板子的中断寄存器）
        │                          清中断标志、EOI（End Of Interrupt，结束中断）
        ▼
③ 通用内核层  kernel/kernel/src/    irq.c：分发到具体处理
             irq.c / interrupt.c    - 定时器 → 调度
                                    - 其他硬件中断 → 派发给注册了该中断的用户进程
```

第 ③ 层有个微内核特色：硬件中断可以**转发给用户态驱动进程**
（[interrupt.c](../../kernel/kernel/src/interrupt.c)）：

```c
int32_t interrupt_setup(proc_t* cproc, uint32_t interrupt,
                        ewokos_addr_t entry, ewokos_addr_t data);
int32_t interrupt_send(context_t* ctx, uint32_t interrupt);
```

流程是：驱动进程（如 `uartd`）调用 `SYS_INTR_SETUP` 告诉内核
"IRQ xx 归我管"；中断到来时内核把驱动进程唤醒（像收到一个事件），
驱动处理完调用 `SYS_INTR_END` 让内核通知硬件"我处理完了"。
**硬件中断的处理代码运行在用户态**——这正是微内核的精髓，
也是"驱动崩溃不会拖死系统"的原因。

## 6.7 关中断：内核的自我保护

内核修改共享数据（如就绪队列）时最怕被中断打断，改到一半被调度走，
数据就处于不一致状态。所以内核代码中常见这样的模式：

```c
__irq_disable();      // 关中断（写 DAIF 寄存器 / CPSR）
... 临界区操作 ...
__irq_enable();       // 开中断
```

`kprintf` 往串口输出时也这么做（防止多核多进程的输出交错）：

```c
// kernel/lib/src/kprintf.c（示意）
__irq_disable();
mcore_lock(&_kout_spin);   // SMP：还要拿自旋锁（多核同时写）
... 写 UART ...
mcore_unlock(&_kout_spin);
__irq_enable();
```

> 关中断不能太久！关中断期间所有事件都被冻结。这就是为什么中断处理程序
> 要尽量短——重活留给内核线程或用户态驱动慢慢做。

## 6.8 动手练习

1. 在 `machines/raspix/system` 启动系统后运行 `ps`，
   观察各进程的 `cpu` 时间统计——它们全部来自定时器中断的记账；
2. 阅读 [irq.c](../../kernel/kernel/src/irq.c) 中处理 `IRQ_TIMER0` 的分支，
   确认"定时器中断 → `schedule()`"这条路径；
3. 思考题：如果定时器中断频率调成 1（每秒一次），系统会发生什么？
   （提示：进程时间片变成 1 秒，交互程序会明显卡顿。可以改
   `/etc/kernel/kernel.conf` 的 `timer_freq` 实际体验。）

## 6.9 本章小结

- 中断让硬件主动打断 CPU，代替低效的轮询；
- 中断处理四步模板：使能 → 识别 → 处理 → 清标志（忘清标志 = 卡死）；
- 中断控制器（GIC/博通中断控制器）汇集和分发中断，内核通过寄存器使能/屏蔽；
- 定时器中断以 `timer_freq`（默认 1024）次/秒的心跳驱动抢占式调度——
  这是系统"活过来"的时刻；
- 中断处理分三层：汇编保存现场 → 板级识别中断 → 通用内核分发；
- 微内核把硬件中断转发给用户态驱动进程处理；
- 临界区用关中断/自旋锁保护，但要尽量短。
