# 03 第一个裸机程序：让树莓派说话

> 本章目标：从零开始写一个程序，不依赖任何操作系统，
> 在 QEMU 模拟的树莓派 3B 上通过串口打印 "Hello, OS!"。
> 这就是所有操作系统内核的最原始形态。
> 本章术语（MMIO/UART/GPIO/BSS/ELF…）见 [附录·术语表](99-术语表-专业名词速查.md)。

学完本章你将理解：
- 树莓派上电后程序是怎么被加载执行的；
- 什么是 MMIO（内存映射 IO），CPU 如何与硬件对话；
- 链接脚本是什么，为什么裸机程序必须自己写一个；
- EwokOS 内核启动的第一段代码长什么样。

## 3.1 树莓派是怎么开机的

普通电脑开机时，BIOS/UEFI 会找到硬盘上的引导程序。树莓派不同，
它的启动由 **GPU 固件** 主导：

```
① 上电。SD 卡必须是 FAT32 分区，里面有树莓派官方固件文件
   （bootcode.bin、start.elf、*.dtb 等，本仓库在 tools/bootfs/raspix/ 里）
② GPU 读取 SD 卡上的 config.txt 配置文件
③ config.txt 里写着内核文件名：
   - 64 位：kernel8.img → 加载到内存 0x80000，CPU 以 AArch64 模式启动
   - 32 位：kernel7.img → 加载到内存 0x8000，CPU 以 ARMv7 模式启动
④ CPU 从加载地址开始执行——这就是我们的代码！
```

所以内核开发的第一件事就是：**产出一个二进制文件 `kernel8.img`，
让 GPU 固件把它放到内存 0x80000，然后 CPU 从那里开始跑**。

仓库里的对应配置见
[config.mk](../../machines/raspix/kernel/config.mk)：

```make
ARCH        = aarch64
LOAD_ADDRESS = 0x80000      # 内核加载地址
QEMU_MACHINE = raspi3b
```

> **为什么是 0x80000？** 没有为什么，这是树莓派固件的约定（32 位是 0x8000）。
> 后面第 05 章你会看到，链接脚本必须把代码放到这个地址，否则启动即死。

## 3.2 CPU 上电后的第一条指令：只能是汇编

CPU 刚上电时：没有栈、没有 C 运行时、甚至可能处于多个核心同时运行的状态。
C 语言无法在这种状态下直接工作（C 需要栈），所以**所有内核的第一段代码都是汇编**。

在任意目录创建你的第一个内核项目（建议放在仓库外，比如 `~/os/hello`）：

```bash
> mkdir -p ~/os/hello && cd ~/os/hello
```

### start.S —— CPU 上电后执行的第一段代码

```asm
// start.S：树莓派 3B 上电后从这里开始执行（AArch64 模式）
.section ".text.boot"      // 放进一个专门的段，链接脚本会让它排在最前面
.global _start             // _start 是入口符号

_start:
    // ---- 第一步：只留 0 号核心，让其他 3 个核心休眠 ----
    // 树莓派 3B 有 4 个核心同时上电。不处理的话 4 个核心会同时执行
    // 我们的代码，互相踩坏。mpidr_el1 寄存器保存着当前核心编号。
    mrs     x1, mpidr_el1   // 读取核心编号到 x1
    and     x1, x1, #3      // 编号在最低 2 位
    cbz     x1, 2f          // 如果是 0 号核心，跳到标号 2 继续启动
1:  wfe                     // 其他核心：低功耗等待（永远等下去）
    b       1b

2:
    // ---- 第二步：设置栈指针 ----
    // C 语言的函数调用、局部变量全靠栈。我们把栈顶设为内核镜像的起始地址
    // （0x80000 上方是空闲内存，下方没有东西，向下生长正好安全）。
    ldr     x1, =_start     // x1 = 0x80000（由链接脚本决定）
    mov     sp, x1          // sp 就是栈指针寄存器

    // ---- 第三步：清零 BSS 段 ----
    // 未初始化的全局变量放在 BSS 段，它不占镜像空间，
    // 文件里根本没有它们的数据，必须手动清零，否则值是随机的。
    ldr     x1, =__bss_start
    ldr     w2, =__bss_size // 需要清零的 8 字节块数（由链接脚本算好）
3:  cbz     w2, 4f          // 清零完毕
    str     xzr, [x1], #8   // 写入 0，地址前进 8 字节
    sub     w2, w2, #1
    cbnz    w2, 3b          // 没清完，继续

4:
    // ---- 第四步：进入 C 语言世界 ----
    bl      main            // 调用 main 函数
5:  wfe                     // main 竟然返回了？让 CPU 低功耗挂起
    b       5b
```

关键指令注释：
- `mrs`：把系统寄存器读到通用寄存器；
- `cbz/cbnz`：比较并跳转（值为 0 / 非 0）；
- `wfe`：Wait For Event，CPU 休眠直到有事件；
- `bl`：带返回的跳转（即函数调用）；`b`：无条件跳转。

### main.c —— 驱动串口打印

串口（**UART**，Universal Asynchronous Receiver/Transmitter，通用异步收发器）
是调试内核的生命线：没有屏幕、没有文件系统，
但一根串口线就能看到 CPU 在想什么。树莓派 3B 上我们使用 **Mini UART**
（精简版 UART），它挂在 **GPIO**（General Purpose Input/Output，
通用输入输出引脚）14/15 上。

硬件手册告诉我们：树莓派 3B 所有外设的寄存器都被映射在物理地址
`0x3F000000` 开始的一段内存里（这叫 **MMIO**，Memory-Mapped I/O，
内存映射输入输出——把设备寄存器当成内存地址来读写）。
**往这些"地址"写数据，就等于在操作硬件**。

```c
// main.c：初始化 Mini UART 并打印
typedef unsigned int uint32_t;

// 直接读写物理地址。volatile 防止编译器优化掉这些"看起来没用"的读写
#define MMIO_BASE 0x3F000000
#define reg(r) ((volatile uint32_t*)(MMIO_BASE + (r)))

// --- Mini UART 寄存器（偏移见 BCM2837 手册） ---
#define AUX_ENABLES  0x215004   // 外设使能
#define MU_IO        0x215040   // 收发数据
#define MU_IER       0x215044   // 中断使能
#define MU_IIR       0x215048   // FIFO 控制
#define MU_LCR       0x21504C   // 数据位宽
#define MU_MCR       0x215050
#define MU_LSR       0x215054   // 线路状态
#define MU_CNTL      0x215060   // 收发使能
#define MU_BAUD      0x215068   // 波特率

// --- GPIO 寄存器：把 14/15 引脚切换成串口功能 ---
#define GPFSEL1      0x200004   // 引脚 10~19 的功能选择
#define GPPUD        0x200094   // 上拉/下拉控制
#define GPPUDCLK0    0x200098

static void delay(int32_t count) {
    while(count-- > 0)
        ;
}

static void uart_init(void) {
    // 1. 打开 Mini UART 外设电源开关
    *reg(AUX_ENABLES) = 1;

    // 2. 配置串口：关中断、8 位数据、清 FIFO
    *reg(MU_IER)  = 0;
    *reg(MU_LCR)  = 3;        // 8 位数据
    *reg(MU_MCR)  = 0;
    *reg(MU_IIR)  = 0xC6;     // 清空收发缓冲区
    *reg(MU_BAUD) = 270;      // 115200 波特率（时钟 250MHz 时的计数值）

    // 3. 把 GPIO 14/15 配置为串口功能（ALT5）
    uint32_t ra = *reg(GPFSEL1);
    ra &= ~(7 << 12);         // 清掉 GPIO14 的功能位
    ra |=  2 << 12;           // 100(ALT5)... 010 = ALT5
    ra &= ~(7 << 15);         // 清掉 GPIO15 的功能位
    ra |=  2 << 15;
    *reg(GPFSEL1) = ra;

    // 4. 关闭这两个引脚的上拉/下拉（时序要求先等 150 个时钟周期）
    *reg(GPPUD) = 0;
    delay(150);
    *reg(GPPUDCLK0) = (1 << 14) | (1 << 15);
    delay(150);
    *reg(GPPUDCLK0) = 0;

    // 5. 使能发送/接收
    *reg(MU_CNTL) = 3;
}

static void uart_putc(char c) {
    // 等发送缓冲区有空位（LSR 第 5 位为 1 表示可发送）
    while(!(*reg(MU_LSR) & 0x20))
        ;
    *reg(MU_IO) = c;
}

static void uart_puts(const char* s) {
    while(*s) {
        if(*s == '\n')
            uart_putc('\r');   // 终端换行需要 \r\n 两个字符
        uart_putc(*s++);
    }
}

void main(void) {
    uart_init();
    uart_puts("Hello, OS! I am a bare-metal kernel.\n");
    while(1)
        ;
}
```

这就是驱动程序最原始的样子：**查手册 → 找到寄存器地址 → 读写内存**。
以后每学一个设备（SD 卡、显卡、中断控制器）都是这个套路。

### kernel.ld —— 链接脚本：告诉链接器内存怎么摆放

普通程序由操作系统加载，链接器用默认布局即可。裸机程序没有谁替它摆放，
必须自己声明：**代码从哪个地址开始、各个段放在哪**。

```
/* kernel.ld */
ENTRY(_start)                    /* 入口符号是 _start */

SECTIONS
{
    . = 0x80000;                 /* 从 GPU 约定的加载地址开始 */
    .text.boot : { *(.text.boot) } /* 启动汇编必须排第一！ */
    .text :  { *(.text) }        /* 其余代码 */
    .rodata : { *(.rodata) }     /* 只读数据（字符串常量等） */
    .data : { *(.data) }         /* 已初始化全局变量 */

    . = ALIGN(8);                /* 8 字节对齐 */
    __bss_start = .;             /* 定义符号，供 start.S 引用 */
    .bss : { *(.bss COMMON) }    /* 未初始化全局变量 */
    __bss_end = .;
}

__bss_size = (__bss_end - __bss_start) >> 3;   /* 多少个 8 字节 */
```

> `.text.boot` 排第一至关重要：文件开头 8 字节处必须是跳转进 `_start` 的指令，
> 因为 GPU 固件就是跳进文件加载后的起始地址。

### Makefile —— 把三个文件变成内核镜像

```make
CC      = aarch64-none-elf-gcc
OBJCOPY = aarch64-none-elf-objcopy
CFLAGS  = -O2 -ffreestanding -nostdinc -nostdlib -Wall \
          -march=armv8-a -mgeneral-regs-only

all: kernel8.img

kernel8.elf: start.S main.c kernel.ld
	$(CC) $(CFLAGS) -T kernel.ld -o kernel8.elf start.S main.c

kernel8.img: kernel8.elf
	$(OBJCOPY) -O binary kernel8.elf kernel8.img

run: kernel8.img
	qemu-system-aarch64 -M raspi3b -kernel kernel8.img -serial null -serial stdio

clean:
	rm -f *.elf *.img
```

参数解释：
- `-ffreestanding -nostdlib`：没有标准库（我们就是标准库的爸爸）；
- `-mgeneral-regs-only`：不生成浮点/NEON 指令（简化启动，第 04 章再解锁）；
- `-T kernel.ld`：使用我们的链接脚本；
- `objcopy -O binary`：把 ELF 剥成纯二进制（GPU 只认二进制，不认 ELF）；
- QEMU `-serial null -serial stdio`：树莓派 3B 有两个串口，
  第一个（PL011）空接，第二个（Mini UART）接到你的终端。

## 3.3 对第一套代码的解读：初步认识 ARM 指令和树莓派

代码跑之前，先把刚才用到的"新语言"系统过一遍。
**不要犹豫，汇编其实很简单**——AArch64 常用指令不超过 20 条，
而裸机内核真正用到的只有其中一半。

### ARM CPU 的基本知识：首次解读寄存器

CPU 内部有一小撮**寄存器**——比内存快几十倍的"手边草稿纸"。
AArch64 模式下它们的分工：

| 寄存器 | 作用 | 你会在哪遇到它 |
|---|---|---|
| `x0` ~ `x30` | 31 个 64 位通用寄存器，`w0`~`w30` 是它们的低 32 位 | 所有计算与传参 |
| `sp` | 栈指针：当前栈顶的地址 | start.S 里第一条实用指令就是设它 |
| `pc` | 程序计数器：正在执行哪条指令 | 跳转/异常时它在变 |
| `xzr`/`wzr` | 恒零寄存器：读它永远是 0，写它等于丢弃 | 清 BSS 时 `str xzr,[x1]` |
| `x30`(lr) | 链接寄存器：`bl` 跳转时保存返回地址 | 函数调用 |
| `x29`(fp) | 帧指针：标记当前函数栈帧 | 调试时看调用栈 |

另一类是**系统寄存器**（用 `mrs`/`msr` 指令访问），
操作系统几乎只跟这几个打交道：

| 系统寄存器 | 作用 | 出现章节 |
|---|---|---|
| `mpidr_el1` | 当前是几号核心 | 本章（停从核） |
| `CurrentEL` | 当前特权级（EL0/1/2） | 第 04 章 |
| `VBAR_EL1` | 异常向量表地址 | 第 04 章 |
| `ELR_EL1` / `SPSR_EL1` | 异常发生时的返回地址 / 现场状态 | 第 04 章 |
| `TTBR0_EL1` / `TTBR1_EL1` | 页表基地址（虚拟内存的翻译表在哪） | 第 05 章 |
| `SCTLR_EL1` | 总开关：MMU、缓存等 | 第 05 章 |

> `_el1` 后缀表示"EL1（内核）视角的寄存器"。同名的 `_el0`/`_el2`
> 是其他特权级的版本。这个命名规则贯穿全书。

### 函数调用约定：参数怎么传

C 函数编译成汇编后，参数传递遵循固定约定（AAPCS64）：

```
第 1~8 个参数：x0, x1, x2, x3, x4, x5, x6, x7
返回值：      x0
被调用者必须保护（用完恢复）：x19 ~ x28
随便用不用还：x0 ~ x18（调用者自己负责）
```

这个约定现在只需眼熟，第 04 章你会亲手在汇编里给 C 函数传参，
第 08 章系统调用的参数传递也是同一套规则（x0 放调用号，x1~x3 放参数）。

### 本章用到的指令全表

| 指令 | 含义 | 本章用例 |
|---|---|---|
| `mov x1, x2` | 赋值 | `mov sp, x1` |
| `ldr x1, =符号` | 把符号的地址/常量装入寄存器 | 取 `_start`、`__bss_start` 地址 |
| `str x1, [x2]` | 把 x1 存到地址 x2 处；`[x1], #8` 表示存完后地址加 8 | 清 BSS |
| `and/orr` | 按位与/或 | 提取核心编号、设置 GPIO 功能位 |
| `sub w2, w2, #1` | 减法 | 循环计数 |
| `cbz/cbnz x1, 标号` | 为 0/非 0 则跳转 | 循环与分支 |
| `b 标号` / `bl 标号` | 跳转 / 调用（保存返回地址） | `bl main` |
| `wfe` | 休眠等待事件 | 停掉从核 |
| `mrs x1, 系统寄存器` | 读系统寄存器 | 读核心编号 |

### 亲眼验证：反汇编你的内核

"解读代码"最好的办法是看编译器生成的真东西：

```bash
> aarch64-none-elf-objdump -d kernel8.elf | less
```

找到 `<main>:` 一段，对照 `main.c` 源码看：你会发现 `*reg(MU_IO) = c`
变成了 `ldr`（算地址）+ `str`（写内存）两条指令——
**所谓驱动硬件，最终就是读写地址**，汇编把这一点暴露无遗。

## 3.4 运行！

```bash
> make run
Hello, OS! I am a bare-metal kernel.
```

**恭喜你！你写出了第一个内核。** 刚才发生的事：

1. QEMU 模拟树莓派固件，把 `kernel8.img` 载入内存 `0x80000`；
2. CPU 从 `_start` 开始：停掉多余核心、设栈、清 BSS、进入 `main`；
3. `main` 按手册配置 GPIO 和 UART，逐个字符把数据推向物理寄存器；
4. 数据经过虚拟的串口线出现在你的终端上。

## 3.5 对照阅读：EwokOS 是怎么做的

现在回头看仓库，你会发现同样的结构，只是更完整：

| 本章手写代码 | EwokOS 对应实现 |
|-------------|----------------|
| `start.S` | [boot.S](../../kernel/platform/aarch64/arch/v8/boot.S) —— 同样关中断、设栈、停从核，但还要处理 EL2→EL1 特权级切换（第 04 章） |
| 链接脚本 `kernel.ld` | [mkos.lds.S](../../machines/raspix/kernel/mkos.lds.S) —— 地址由 `config.mk` 的 `LOAD_ADDRESS` 传入 |
| `uart_init/uart_putc` | [mini_uart.c](../../machines/raspix/kernel/lib/bcm283x/src/mini_uart.c) —— 几乎和你写的一模一样 |
| `main()` | [_kernel_entry_c](../../kernel/kernel/src/kernel.c) —— 初始化内存、串口、进程表，加载 init |

重点看 `mini_uart.c`，它和我们的代码唯一的不同是寄存器基地址：

```c
// 手写版：直接写死物理地址 0x3F000000
#define MMIO_BASE 0x3F000000

// EwokOS 版：通过 MMU 映射后的虚拟地址访问（第 05 章详解）
#define UART_BASE (_sys_info.mmio.v_base | UART_OFFSET)
```

再感受一下 EwokOS 内核的"main 函数"
（[kernel.c](../../kernel/kernel/src/kernel.c)，节选）：

```c
void _kernel_entry_c(void) {
    memset(_bss_start, 0, ...);        // 和你的 start.S 一样：清 BSS
    sys_info_init();                   // 收集硬件信息（内存大小、MMIO 地址）
    init_kernel_vm();                  // 建立内核虚拟内存（第 05 章）
    uart_dev_init(19200);              // 初始化串口（就是你刚写的东西！）
    kout_str("\n=== ewokos booting ===\n\n");
    kmalloc_init();                    // 内核内存分配器
    sd_init();                         // SD 卡驱动（第 10 章）
    load_kernel_config();              // 读配置文件
    irq_init();                        // 中断（第 06 章）
    procs_init();                      // 进程表（第 07 章）
    load_init_proc();                  // 加载第一个用户进程 /sbin/init（第 11 章）
    timer_set_interval(0, _kernel_config.timer_freq);  // 定时器心跳
    __irq_enable();                    // 打开中断
    halt();                            // 内核进入调度循环
}
```

整个内核启动流程，就是这十几行里的每一行。接下来 10 章我们逐一攻破。

## 3.6 不要犹豫，汇编其实很简单：C 与汇编混合编程

很多人卡在"不敢写汇编"。现在用一个小实验打破它：
**把 `uart_putc` 改写成纯汇编，让 C 代码调用它**。
这就是 EwokOS 里汇编与 C 协作的真实方式（内核中 `syscall`、
上下文切换都是这么写的）。

### 第一步：写汇编版 `uart_putc`

新建 `uart_asm.S`：

```asm
// uart_asm.S：用汇编实现 uart_putc(char c)
// 按调用约定，第一个参数 c 在 x0 寄存器里

#define MMIO_BASE 0x3F000000
#define MU_IO     0x215040        // 数据寄存器
#define MU_LSR    0x215054        // 状态寄存器

.global uart_putc_asm
uart_putc_asm:
    mov     x9, x0                  // x0 是参数，先保护起来
    ldr     x10, =(MMIO_BASE + MU_LSR)
1:  ldr     w11, [x10]              // 读线路状态
    and     w11, w11, #0x20         // 取"发送缓冲区空"位
    cbz     w11, 1b                 // 没空？继续等
    ldr     x10, =(MMIO_BASE + MU_IO)
    str     w9, [x10]               // 把字符写进数据寄存器
    ret                             // 返回（跳回 x30 保存的地址）
```

逐行看，没有任何新东西：`mov`、`ldr`、`str`、`and`、`cbz`、`ret`
全是本章已见过的指令。**所谓汇编编程，就是"寄存器倒来倒去 + 读写地址 + 跳转"三件事**。

### 第二步：C 里声明并调用

汇编函数对 C 来说就是一个"普通函数"，声明即可：

```c
extern void uart_putc_asm(char c);   // 声明：实现在 .S 文件里

void main(void) {
    uart_init();
    uart_putc_asm('A');              // C 调用汇编
    uart_putc_asm('\r');
    uart_putc_asm('\n');
    while(1);
}
```

Makefile 里把 `uart_asm.S` 加进编译列表：

```make
kernel8.elf: start.S main.c uart_asm.S kernel.ld
	$(CC) $(CFLAGS) -T kernel.ld -o kernel8.elf start.S main.c uart_asm.S
```

`make run`，看到 `A` 就说明你完成了第一次 C/汇编混合编程。

### 参数传递机制：串起来看

这一来一回，参数传递的完整链条是：

```
C:    uart_putc_asm('A')
  ↓   编译器生成：mov w0, #65     （第 1 个参数 → x0）
  ↓             bl uart_putc_asm  （调用，返回地址存 x30）
汇编:  从 x0 取到 'A'，干活，ret
  ↓   ret 跳回 x30 指向的 C 代码，继续执行
```

如果有多个参数（如 `int add(int a, int b)`），就是 `a→x0, b→x1`，
返回值在 `x0`。第 08 章的系统调用将原样复用这条通道。

> 对照真实代码：EwokOS 的系统调用入口
> [syscall_aarch64.S](../../system/basic/libc/libewoksys/ewoksys/src/syscall_aarch64.S)
> 只有两条指令 `svc #0` + `ret`——比你现在写的还短。汇编不可怕，它只是直接。

## 3.8 本章小结

- 树莓派由 GPU 固件加载内核：64 位叫 `kernel8.img`，放在内存 `0x80000`；
- 内核第一段代码必须是汇编：停从核、设栈、清 BSS，然后进入 C；
- 硬件通过 MMIO 访问：读写特定物理地址 = 操作硬件寄存器；
- 链接脚本决定代码和数据的内存布局；
- 汇编就是"寄存器倒腾 + 读写地址 + 跳转"；C 与汇编通过 x0~x7 寄存器传参；
- EwokOS 的启动代码与本章结构一致，只是多了特权级切换和 MMU。
