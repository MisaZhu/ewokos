# 14 制作镜像并烧录到树莓派

> 本章目标：把整个系统装进 SD 卡，在真实树莓派上启动。
> 包括：构建产物盘点、SD 卡分区布局、config.txt、烧录步骤、串口观察。

## 14.1 树莓派需要什么样的 SD 卡

回顾第 03 章的启动约定。SD 卡必须是这样的布局：

```
SD 卡
├── 分区 1（FAT32，卷标 bootfs）       ← GPU 固件只认 FAT32
│   ├── bootcode.bin / start.elf / fixup.dat   GPU 固件
│   ├── bcm2710-rpi-3-b.dtb 等                 设备树（各型号）
│   ├── config.txt                             启动配置
│   └── kernel8.img                            ★ 我们的内核
│
└── 分区 2（ext3，卷标 rootfs）
    └── 完整根文件系统（/bin /sbin /etc /drivers ...）
```

GPU 固件（`bootcode.bin` 等）和所有板子的 `config.txt` 模板
都在 [tools/bootfs/raspix/](../../tools/bootfs/raspix/) 里，开箱即用。

`config.txt` 的关键内容（[config.txt](../../tools/bootfs/raspix/config.txt)）：

```ini
[all]
arm_64bit=1          # 64 位启动（加载 kernel8.img）
enable_uart=1        # 使能串口（看启动日志必备）
force_turbo=1

[pi3]
core_freq=250        # 固定 GPU 时钟 → Mini UART 波特率稳定
...
```

## 14.2 构建所有产物

```bash
> cd machines/raspix/system
> make          # 生成 ../kernel/kernel8.img 和 rootfs
> make sd       # 把 rootfs 打包成 root_aarch64.img（512MB ext3 镜像）
```

产物位置：

| 文件 | 说明 |
|------|------|
| `machines/raspix/kernel/kernel8.img` | 内核（放分区 1） |
| `machines/raspix/system/root_aarch64.img` | 根文件系统镜像（写入分区 2） |

> **重要避坑**：单独编译某个驱动/应用目录，只会更新
> `system/build/aarch64/raspix/rootfs/` 下的文件，
> **不会**更新 `root_aarch64.img`。烧卡前必须重新 `make sd`，
> 否则烧进去的是旧系统。拿不准时对比文件时间戳：
> `ls -l root_aarch64.img` 要比刚编译的二进制新。

## 14.3 制作 SD 卡（macOS）

仓库提供了一键分区脚本 [tools/makesd.sh](../../tools/makesd.sh)。
它做的事：卸载所有分区 → 建 MBR 分区表 → 分区 1 格式化为
FAT32（卷标 `bootfs`）→ 分区 2 用 `mke2fs -t ext3 -b 4096 -I 128` 格式化。

```bash
# 先确认 SD 卡的设备号（千万确认好，别选成你的硬盘！）
> diskutil list
> sudo tools/makesd.sh /dev/disk4
```

然后：

```bash
# 1. 把固件和内核写进分区 1（FAT32，macOS 直接挂载）
> cp tools/bootfs/raspix/* /Volumes/bootfs/
> cp machines/raspix/kernel/kernel8.img /Volumes/bootfs/
> diskutil unmountDisk /dev/disk4
```

**注意**：macOS 无法挂载 ext3，所以分区 2 的内容必须在
Linux 环境（或 Linux 虚拟机/QEMU）里写入。两种方式：

```bash
# 方式 A（推荐，Linux 上）：直接把镜像 dd 进分区 2
> sudo dd if=systems/raspix/root_aarch64.img of=/dev/sdX2 bs=1M
> sudo e2fsck -f /dev/sdX2   # 校验

# 方式 B（Linux 上）：挂载分区后用 e2cp 拷入
> sudo e2cp -rap rootfs目录/* /dev/sdX2:/
```

> 不要在 macOS 上"想办法"挂载 ext3 拷文件——
> 第三方驱动会破坏权限、符号链接和设备节点。

## 14.4 制作 SD 卡（Linux）

```bash
> lsblk                                # 确认设备号，例如 /dev/sdX
> sudo tools/makesd.sh 不可用时，手动分区：
> sudo parted /dev/sdX mklabel msdos
> sudo parted /dev/sdX mkpart primary fat32 4MiB 132MiB
> sudo parted /dev/sdX mkpart primary ext3 132MiB 100%
> sudo mkfs.vfat -F 32 -n bootfs /dev/sdX1
> sudo dd if=.../root_aarch64.img of=/dev/sdX2 bs=1M
> sudo mount /dev/sdX1 /mnt/boot
> sudo cp tools/bootfs/raspix/* machines/raspix/kernel/kernel8.img /mnt/boot/
```

## 14.5 接上串口，见证启动

强烈建议用 USB 转 TTL 串口线观察启动过程（也作为交互终端）：

```
USB-TTL 线            树莓派 40Pin 排针
─────────────────────────────────────
GND（黑）  ──────────► Pin 6  (GND)
RXD（白）  ──────────► Pin 8  (GPIO14 TXD)
TXD（绿）  ──────────► Pin 10 (GPIO15 RXD)
```

> 交叉连接：线的 RX 接树莓派的 TX，线的 TX 接树莓派的 RX。
> 先接好线再上电。

电脑上打开串口终端：

```bash
# macOS
> screen /dev/tty.usbserial-XXXX 115200     # Ctrl-A K 退出

# Linux
> minicom -D /dev/ttyUSB0 -b 115200
```

插入 SD 卡、接好线、上电。几秒后串口里出现熟悉的：

```
=== ewokos booting ===
kernel: init kernel malloc     ... [OK]
...
-----------------------------------------------------
 ______           ______  _    _ ...
```

接着是 init 启动各服务，最后出现提示符——
**这是你自己的操作系统，在真实硬件上运行**。

如果没有图形输出也不用慌：先用串口确认系统正常，
再检查 HDMI/显示器与 `config.txt` 的显示配置。

## 14.6 真机调试注意事项

来自实践的经验：

1. **QEMU 测不到的硬件只能真机测**：树莓派的 SDIO/WiFi（`wland`）
   等硬件 QEMU 不模拟，相关改动只能烧卡验证；
2. **改完必烧新镜像**：参考 14.2 的避坑提示；
3. 真机崩溃没有 GDB，串口日志是第一现场——养成在可疑路径加
   `klog/slog` 的习惯（第 15 章）；
4. 不同型号差异：Pi2/3 的 MMIO 基址是 `0x3F000000`，Pi4 是 `0xFE000000`
   ——这就是 [start.c](../../machines/raspix/kernel/bsp/start.c)
   里按 CPU 型号分支映射页表的原因。

## 14.7 动手练习

1. 完整走一遍：构建 → 烧卡 → 串口启动，截图你的第一次真机启动；
2. 修改 `config.txt` 的 `enable_uart=0`，观察会发生什么再改回来；
3. 在真机上运行你在第 12 章写的 `hello` 命令。

## 14.8 本章小结

- SD 卡两分区：FAT32 bootfs（固件+config.txt+内核）+ ext3 rootfs；
- `make sd` 产出根文件系统镜像；改完系统必须重新打包；
- macOS 负责分区与 bootfs，ext3 rootfs 的写入要在 Linux 环境进行；
- 串口线是实机开发的生命线。
